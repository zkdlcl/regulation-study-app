# 기출 근거 DB로 카드·문제·검수

Claude 는 규정을 완벽히 알지 못하고 대화가 끝나면 잊는다. 그래서 **판단의 근거는 언제나 두 가지뿐**이다.
1. 규정 원문 — `python -X utf8 kb/work.py --art 규정:조문`
2. 기출 근거 DB — `kb/exam_kb.json` (요약: `kb/기출기준.md`)

## 시작 전에 (매번)
0. 누가(임용·징계·승인·처분) 하는지가 걸리면 `kb/조직구조.md` 를 먼저 읽는다. 지사·혈액관리본부·의료원·직할기관은 같은 단계의 '기관', 혈액원·병원 등은 그 아래 '소속기관'이다.
0-1. **`kb/study/가채점오류.md` 를 먼저 읽는다** — 공식 답지 전에 Claude 가 가채점했다가 틀린 사례와 교훈(출제자는 원문 글자 기준으로 엄격히 채점: 단위·한정어·연장 숫자·조문 섞기 하나만 달라도 X). '출제 의도상 O' 같은 관대한 판정을 하지 않는다.
1. `python -X utf8 tools/kbq.py digest <규정>` — 기출기준.md 의 그 규정 절만: 자주 나온 조문, 형식·묻는 것·난이도 분포, 함정 목록.
2. 다룰 조문 원문 + 그 조문의 기출 id·함정을 `python -X utf8 tools/kbq.py art 규정:조문` 으로 읽는다. 기억에 의존하지 않는다.
3. 기출 문항 본문·근거 기록은 `python -X utf8 tools/kbq.py item <id...>` (한 번에 몇 개씩).

## 컨텍스트 아끼기 (훅이 지킨다)
- `kb/exam_kb.json`, `kb/annot/*.json`, `regs.json`, `site/data/**`, `orgmaster*.html`, `dist/`, `base/*.html` 은 **통독 금지** — `tools/ctx_guard.py` 훅이 막는다. 조회는 `tools/kbq.py`, 낱말 찾기는 Grep(`-n`, `head_limit`).
- 5문항(또는 조문 묶음) 단위로 일한다. 묶음이 끝나면 `python -X utf8 tools/kbq.py checkpoint --줄 <작업 줄> "<한 일·다음 할 일 한 줄>"` (덧붙이기만, 병렬 세션 안전).
- 컨텍스트 알림(실측 70%·85%)이 오면 지금 묶음을 마치고 체크포인트를 남긴 뒤 새 세션을 권한다. 새 세션은 `kb/진행/` 작업 줄 요약을 자동으로 받는다.

## 공부 세션 절차 (인출 → 확신도 → 채점 → 오답 큐)
1. 시작: `python -X utf8 tools/kbq.py wrong due` — 오늘 차례인 오답부터 낸다(확신 오답이 먼저 나온다). 원문은 `kbq.py art` 로 다시 확인.
2. 새 묶음은 5문항 안팎. 해설·표를 먼저 보여 주지 않는다(인출 먼저). 헷갈리는 조문끼리 섞는다.
3. 답과 함께 확신도 `확실·애매·찍음` 을 받는다(예: `1 O 확실`). 안 적으면 한 번만 물어본다.
4. 채점: 틀린 보기는 해설 전에 "원문에서 바뀐 낱말"을 먼저 묻고, 그다음 원문 인용으로 판정한다.
5. 기록: 새로 틀린 것 → `wrong add <규정:조문> <정답> <확신> "<원문 기준 문장>" "<함정 낱말>"`, 큐에서 낸 것 → `wrong hit <id> 맞음|틀림 [확신]`. **맞았어도 '찍음'이면 add 한다**(우연히 맞은 것).
6. 끝: 점수·확신 오답 수를 한 줄로, `checkpoint --줄 오답공부 "…"`, 자기 줄 파일 `다음:` 갱신.

## 문제를 낼 때
- 형식·난이도는 그 규정의 기출 분포를 따른다(예: 운영규정은 '정오-틀린것'·'개수' 형식이 많다면 그 비율로).
- 보기는 **원문 문장을 그대로** 쓰고, 틀린 보기는 원문의 낱말 하나를 바꿔 만든다. 바꿀 낱말은 `traps` 에 나온 것(실제 시험 함정)을 먼저 쓴다.
- 문제마다 정답과 함께 **근거: 규정 제N조 + 원문 인용**을 붙인다. 인용할 수 없는 내용은 문제로 내지 않는다.
- `kb/조직구조.md` 의 **예정 변경(미확정)** 에 걸리는 숫자(예: 대의원총회 인원)는 지금 원문 기준으로 내고 "바뀔 수 있음"을 덧붙인다.
- 개정된 조문(`status: 개정차이`)은 **지금 원문 기준**으로 내고, 옛 기출과 다르다고 알려 준다.

## 카드를 만들 때
- 카드 문장은 원문 그대로, 빈칸은 원문 낱말 그대로 (`make_cards.py` 규칙 참고).
- 기출에 나온 조문·함정 낱말을 먼저 카드로 만든다. 기출에 없는 조문은 뒤로 미룬다.
- 바꾼 뒤엔 `python -X utf8 make_cards.py --progress backup/progress.json` 으로 학습 기록이 있는 카드가 빠지지 않는지 확인한다.

## 답·해설을 검수할 때
- 사용자의 답이 맞는지는 원문 인용으로만 판정한다. "아마", "일반적으로" 같은 추측으로 판정하지 않는다.
- 근거를 찾지 못하면 **모른다고 말하고** 원문 위치를 함께 찾자고 한다. 기출 해설과 지금 원문이 다르면 둘 다 보여 준다.
- 검수 중 DB 기록이 틀렸음을 발견하면 `kb/annot/` 을 고치고 `kb/check_kb.py` 를 다시 돌린다(kb-annotate 스킬).

## 스터디 답지가 나오면
- `kb/study/답지.json` 의 `items`(앱에 있던 문항) 또는 `add`(새 문항)에 공식 답·근거 인용을 적고 `python -X utf8 kb/study/check_study.py` 로 검사한다. 가채점과 답이 다르면 `verdict: 가채점오류` + why·lesson·ex 필수 → `가채점오류.md` 가 다시 만들어진다.
- 빌드가 앱 문제에 답·해설을 덮어쓰고, 내 답 seed 의 맞음/틀림이 바뀐 문항은 앱이 한 번만(서버 동기화 뒤) 바로잡는다(`D.stFix`, seeds 플래그 이름은 새로 붙일 것).

## 하지 않는 것
- 원문 없이 기억으로 숫자·주체·기한을 말하기
- 기출에 없는 '출제 경향'을 지어내기
- 사용자의 학습 기록(아티팩트 DB `state/progress`)을 덮어쓰기
